# TOFIX

Findings from a code scan on 2026-10-04, re-checked and extended by a review on 2026-11-15.

## High

- `src/myworld/views.py:112` - `Work` rows are shared between all users (`src/myworld/models.py:116`), yet `_apply_work_ids` lets any signed-in user overwrite `imdb_id`, `tmdb_id` and `rotten_tomatoes_id` on an existing shared work with whatever the request body carries, changing the IMDb/RT links every other user sees for that title. Only fill ids that are currently empty, or resolve ids server-side from `tmdb_id` instead of trusting the client.
- `scripts/import_world.py:459` - the default mode (only `--email`) bulk-deletes the account's concerts, museums, people, organizations, places, groups, cities, countries, types, devices, audio courses, YouTube videos, images and book entries and re-creates them from the YAML; `scripts/import_world_cloud.sh` points it at Cloud SQL. Run again after the user has edited data in the UI, every UI edit and every fetched picture is gone. Refuse when the account already has rows unless an explicit `--replace-everything` (repeating the email) is given; `tests/world_test.py:1014` `test_reimport_replaces` locks in the current behaviour.
- `src/myworld/static/app.js:1790` - People and the six type/device views (`TABLES`) are tables, and `updateTools` (`:816`) disables List/Cards/Tiles/Gallery on them; Users, Checks and Schema are fixed pages. Every view should have the four layouts: add card makers for people and the type views and put them in `CARDS`.
- `src/myworld/static/app.js:546` - `loadEntries` assigns `state.entries` after `await api(...)` without checking `state.kind` is still the one requested; click Books then Films quickly and a late Books response shows books under Films, and an edit PUTs against the wrong kind. Capture the kind before the await and drop stale responses (same pattern in `fillTypeFilter` `:1861` and `openDialog` `:3306`, which can open the old view's form and delete with `WORLDS[state.view]` of the new one).

## Medium

- `src/myworld/views.py:185` - adding a work that is already in the library finds the existing `UserWork` and `_apply_entry_fields` (`:92`) resets everything the body omits: status becomes "done", rating, dates and notes are blanked, and the response is a 200. Return 409 for an existing entry, or apply only the fields present.
- `src/myworld/world.py:559` - `drop_unused_images` deletes every unreferenced image of the user and runs on every save/delete of concerts, museums, courses, organizations, entries; an image uploaded in an open dialog is not referenced until that form is saved, so saving or deleting anything else in between deletes it and the form's save fails with "unknown image". Only drop orphans older than a few minutes (needs `Image.created_at`) or upload and attach in one request.
- `src/myworld/world.py:776` - `_apply_youtube_video` assigns `youtube_id` before the clash query; on an edit the autoflush writes it first and `uq_youtube_video_id` raises an unhandled `IntegrityError` (500) instead of the 409. Run the clash query before assigning (or under `no_autoflush`); tests only cover the POST case.
- `src/myworld/api.py:481` - `text()` has no length limit while columns are `String(n)` (city name 100, postcode 20, email 320, ...); Postgres rejects the overlong value with `DataError` (500), sqlite does not, so tests pass. A NUL byte does the same. Derive the limit from the column or take `max_len`, return 400.
- `src/myworld/__init__.py` - no JSON handler for unhandled `IntegrityError`/500: the check-then-insert races (`auth.py:174` register, `auth.py:70` first login, `world.py:1385` same image twice, `admin.py:358` double-click disable, `views.py:186` concurrent work add, name-clash pre-checks) return an HTML 500. Register a handler that rolls back and returns 409 JSON. The work-add race also is not stopped by `uq_work_identity` when `year` is NULL (NULLs are distinct).
- `src/myworld/world.py:295` - pagination is client-side only: every list endpoint (`api_youtube` holds ~30,000 rows, people, organizations, places, ..., and `views.py:172` the library) loads and serialises all rows, and `api_stats` (`:1173`) loads whole objects to count them in Python. Add `limit`/`offset` with a total, and SQL `count()`/`group_by` in stats.
- `src/myworld/models.py:775` - the Cloud SQL URL is built with an f-string, so a `DB_PASS` (or user/db name) containing `@`, `:`, `/`, `?` or `#` produces a broken URL. Use `sqlalchemy.engine.URL.create("postgresql+pg8000", username=..., password=..., database=..., query={"unix_sock": socket})`.
- `src/myworld/auth.py:187` - `/auth/email/login` has no attempt limiting, so passwords of email accounts can be brute-forced against the public Cloud Run service. Add per-account/per-IP throttling.
- `scripts/migrate.sh:505` - `present` is probed once, so steps guarded on a column another step of the same run creates are skipped: `organizations.headquarters_id` (`:900`, needs `organizations.street`), `cities/countries/groups.image_id` (`:906`, needs the table), `person_organizations.relation_type_id` (`:846`, after the rename). The run still prints "deploy" (`:938`) and the new code then fails on the missing columns until a second run. Re-probe and loop until nothing is needed; only print "deploy" on a clean final probe.
- `scripts/migrate.sh` - no test runs it. The `--local` sqlite path rebuilds `people`/`places` by regex-editing `sqlite_master.sql` (`:235`, `:260`), and nothing compares the migrated schema with `Base.metadata`; `tests/admin_test.py:15` re-implements a step instead. Add a test that seeds a legacy schema, runs `migrate.sh --local` twice, and asserts no rows lost, schema equal to `create_all`, and "up to date" on the second run.
- `scripts/migrate.sh:743` - when both the old and the new table exist, the empty new one is dropped without CASCADE, but `create_all` made tables referencing it (`library_entry_authors` -> `library_entries`, `concert_*` -> `concert_visits`), so the DROP fails and the run-deploy-run flow breaks. Drop the empty dependents first.
- `scripts/geocode.py:70` - no handling of `URLError`/timeouts/429/5xx/bad JSON, and the only commit is at the end (`:295`): one transient error in a run of hundreds of 1.1 s lookups discards every coordinate found. Back off on 429/503, treat a failure as a miss, commit every N rows. Same for `scripts/fetch_pictures.py:77` (only 404 handled) and `scripts/split_addresses.py:123` (one transaction held open, with locks on `places`/`organizations`, across all network calls and the `--drop`).
- `scripts/geocode.py:269` - `--all` overwrites coordinates the user corrected in the dialog, and `scripts/fetch_pictures.py:252` `--all` replaces pictures uploaded in the form (leaving the old `Image` rows behind). Skip hand-set rows (a `location_source` flag; user uploads have an empty `image_source`) unless `--force`.
- `scripts/fetch_pictures.py:130` - a file whose license is empty passes the `NON_FREE` filter and is stored with an empty `image_license` (the summary even says "no license given"). Treat an empty license as a miss.
- `src/myworld/static/app.js:943` - the library add/edit form never disables its submit button (unlike `setupWorldForm` `:3222`), so a double click POSTs twice; and an error from `loadEntries()` after `close()` goes to `dialogError` in the closed dialog, i.e. nowhere. Same post-close problem at `:3236` and in `deleteEditing` `:3375`.
- `src/myworld/static/app.js:25` - `api()` calls `response.json()` before checking `ok`, so a 500/502/504 HTML page surfaces as "Unexpected token '<'" instead of the status (same at `:3027`). Parse with `.catch(() => ({}))` as `uploadPhoto` does.
- `src/myworld/world.py:683` (also `:697`, `:709`, `:901`, and `image_source` at `:590`, `:647`) - website/URL fields are stored without a scheme check and rendered as `href` (`app.js:1233` `websiteDetail`, `:1509` `photoCredit`), so `javascript:` URLs work; `fetch_pictures.py` writes `image_source` too.
